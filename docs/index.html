Poradnik po odcinku

Twój Codex w appce. Bez klucza OpenAI API.

Agent Codexa wbudowany we własną aplikację przez Codex SDK, zalogowany Twoim kontem ChatGPT. Appka to radar konkurencji YouTube na Twoim VPS, dostępna z telefonu, za hasłem: czyta nowe filmy, komentarze i napisy z kanałów konkurencji i układa raport - o co pytają widzowie, na co narzekają, czego jeszcze nikt nie nagrał.

Zero programowania. Plan robi agent, kod pisze agent, Ty podajesz dane i klikasz logowania. Chcesz zbudować coś innego niż radar? Podmieniasz jeden akapit i jedziesz tą samą drogą.

Nie chcesz czytać? Otwórz Claude Code w pustym folderze i wklej ten prompt. Agent poprowadzi Cię przez wszystkie kroki.

Czego potrzebujesz

  • Konto ChatGPT Plus / Pro / Business z dostępem do Codexa.
  • Node.js 22+, Claude Code (npm i -g @anthropic-ai/claude-code) i Codex CLI zalogowany kontem ChatGPT (codex login status).
  • Konto Google - klucz YouTube Data API v3 (darmowy, 10 000 jednostek dziennie). Opcjonalnie konto Apify do napisów (darmowy plan 5 USD/mies.).

  • Nie potrzebujesz klucza OpenAI API, frameworka, Tailscale ani tunelu.
⚠️

Limit jest wspólny. Agent w appce zjada tę samą pulę co Codex na Twoim koncie. Stąd bezpiecznik czasu na każdą turę i limit 3 filmów / 100 komentarzy na kanał.

Appka tylko dla Ciebie. Regulamin OpenAI zabrania współdzielenia konta. Appka dla innych ludzi = Sign in with ChatGPT (dziś open source / lokalnie, serwerowe przez listę oczekujących) albo klucz API. Nigdy przez Twoje konto.

O CO CHODZI

Trzy rzeczy, zanim odpalisz agenta

1

API kontra subskrypcja

Z kluczem API płacisz za każdy token. Na subskrypcji ChatGPT masz limity (okno 5-godzinne i tygodniowe), a przy takiej appce zwykle wychodzi taniej. Ten poradnik jedzie na subskrypcji.

2

Agent SDK = gotowy agent do wpięcia w appkę

Nie piszesz własnego agenta. Codex SDK opakowuje silnik Codexa i pozwala go uruchamiać z własnego kodu: wątki z pamięcią, odpowiedź w zadanym schemacie JSON, sandbox z kontrolą sieci i katalogu, strumień zdarzeń z pracy agenta. I pozwala mu jechać na Twoim koncie ChatGPT.

3

Co buduje radar

Kanały konkurencji → RSS (nowe filmy) + YouTube Data API (komentarze, tytuły, opisy) + opcjonalnie Apify (napisy). Dane pobiera appka, agent tylko je analizuje → raport w trzech kafelkach: pytania widzów, narzekania, luki tematyczne. Drugi przebieg pamięta pierwszy i oznacza pozycje „już zgłaszane”.

Jedno sudo: profil sandboxa Twój klik

Sandbox Codexa sam izoluje komendy agenta, a domyślne zabezpieczenia Dockera (seccomp + AppArmor) blokują mu tę izolację: klatka w klatce (objaw: bwrap: ... Operation not permitted). Naprawa jest w deploy/sandbox/: profil AppArmor radar-bwrap i profil seccomp = domyślne profile Dockera plus userns create, mount, remount, pivot_root, tylko dla kontenera radaru. Załadowanie profilu wymaga jednego sudo (krok 4 promptu) - wpisujesz je sam.

⚠️

Nigdy privileged: true, apparmor=unconfined ani danger-full-access. Nie wyłączaj też kernel.apparmor_restrict_unprivileged_userns dla całego serwera - profil robi to samo, ale tylko radarowi.

Inny dostawca niż Hostinger? Agent pomija wtyczkę, dane SSH podajesz sam.

ZJEDZONE ZA CIEBIE

Pułapki, które wizard już zna

1Sandbox agenta w kontenerze nie startuje

„Nie można utworzyć przestrzeni nazw” / bwrap: ... Operation not permitted. Sandbox Codexa sam izoluje komendy agenta, a domyślne zabezpieczenia Dockera (seccomp + AppArmor) blokują mu tę izolację: klatka w klatce. Naprawa jest w deploy/sandbox/: profil AppArmor radar-bwrap i profil seccomp = domyślne profile Dockera plus userns create, mount, remount, pivot_root, tylko dla kontenera radaru. Jedno sudo (install-sandbox-profile.sh) wpisujesz sam. Nigdy privileged: true, apparmor=unconfined ani danger-full-access.

2Hasło „nie pasuje”, choć jest poprawne

Hash scrypt ma w sobie znaki $, a Docker Compose bierze $cośtam w .env za zmienne i po cichu obcina wartość (w logach variable is not set). Hash w .env zawsze w pojedynczych cudzysłowach. Sprawdzenie: docker compose config | grep PASSWORD_HASH ma pokazać cały hash.

3Appka nie zapisuje plików na serwerze

Właściciel danych. Kontener działa jako zwykły użytkownik; jeśli user: w compose nie zgadza się z właścicielem ./data i ./codex-home, appka nie zapisze plików. id -u na serwerze → user: "UID:GID" w compose, katalogi tworzy ten sam użytkownik.

4Certyfikat się nie wystawia

Domena nie wskazuje na IP serwera (dig +short DOMENA) albo port 80/443 zamknięty w firewallu Hostingera (panel → VPS → Firewall). Caddy loguje przyczynę: docker compose logs caddy.

5YouTube API: 403 accessNotConfigured / quotaExceeded

accessNotConfigured: klucz jest, ale API nie włączone w projekcie Google. Console → Enable APIs → YouTube Data API v3 → Enable (propagacja do 5 min). quotaExceeded: zużyte 10 000 jednostek - poczekaj do północy czasu Pacyfiku i sprawdź, czy appka nie pobiera w pętli.

6Apify: invalid-input ... urls

urls podane jako lista stringów. Ma być lista obiektów {"url": "..."}. Pusty transkrypt = film bez napisów: appka pomija treść, zostają komentarze, raport dostaje ostrzeżenie.

7Dodanie kanału: brak channelId w HTML

YouTube nie wstawia już "channelId" w stronę kanału. Naprawa: <meta itemprop="identifier">, zapas externalId / canonical.

8Kod urządzenia nie pojawia się w panelu

Parser zakłada format 4-4, a CLI wypisuje segmenty różnej długości (4-5, np. J7SZ-MXKP1). Naprawa: templates/device-login.js.

9Przycisk logowania nic nie robi, w konsoli 403

Origin nie zgadza się z RADAR_PUBLIC_URL (np. wejście po IP zamiast po domenie). Wchodź przez https://DOMENA; RADAR_PUBLIC_URL w .env ma mieć dokładnie ten adres.

10Kod jest, logowanie się nie kończy

Wyłączone „Device code authorization”. ChatGPT → Ustawienia → Bezpieczeństwo → włącz, uruchom logowanie od nowa.

11Po zamknięciu appki zostaje proces codex login

Paczka @openai/codex uruchamia osobny proces natywny. Uruchamiaj logowanie jako grupę procesów i kończ całą grupę.

12Test HTTP subagenta: listen EPERM

Sandbox subagenta nie pozwala otworzyć portu. Uruchom test z uprawnieniem do lokalnego nasłuchu; dotyczy testu, nie appki.

13Błąd „not a git repository”

Silnik wymaga repo git i odmawia pracy w data/agent/. Naprawa: skipGitRepoCheck: true.

14Tura trwa i trwa

Za dużo materiału. Limit 3 filmów / 100 komentarzy / 3000 słów, bezpiecznik 10 minut na turę (AbortSignal.timeout(10 * 60_000)).

15finalResponse nie jest JSON-em

Schemat za luźny albo brak outputSchema. Naprawa: additionalProperties: false i wszystkie pola w required - tak jak w docs/schema.json.

16Panel pusty, 0 eventów

Użyty run() zamiast runStreamed(). Przełącz na runStreamed(), wtedy ślad kroków idzie na żywo.

Docker omija ufw, dlatego port appki nie jest publikowany w ogóle (tylko expose), a na świat wychodzi wyłącznie Caddy na 80/443.
